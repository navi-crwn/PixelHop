API & ShareX

Upload from screenshot tools, scripts, bots and apps. Everything is plain HTTP with JSON answers.

Getting started

  1. Create an account (or sign in).
  2. Open Settings → API keys and create a key. It starts with ph_.
  3. Send it with every request: Authorization: Bearer ph_…

Guests can call /api/v1/upload without a key{{if not .GuestUploads}} when the owner allows it (turned off on this server){{end}}; the answer then includes a private delete_url.

ShareX

Create a key in Settings and press Download ShareX config. Double-click the .sxcu file and ShareX sets everything up: every screenshot is uploaded and the link lands on your clipboard.

Configs made for PixelHop 2 (posting to /api/upload.php) keep working.

Upload

POST/api/v1/upload

Send multipart/form-data with one or more files in file, or image links in url (one per line).

FieldMeaning
fileThe image. Repeat the field for several (up to {{.MaxBatch}}, {{.MaxMB}} MB each).
urlInstead of a file: links to images on the web.
expireDelete automatically: 10m 1h 1d 7d 30d 90d. Leave out to keep forever.
slug0 to use only random characters in the link instead of the file name.
album0 to not group several files into an album.
titleAlbum title, when several files are sent.
curl -H "Authorization: Bearer ph_yourkey" \
     -F "file=@holiday.jpg" \
     {{.Base}}/api/v1/upload

Answer:

{
  "success": true,
  "data": {
    "id": "holiday-x7Kp2Q",
    "url": "{{.Base}}/i/holiday-x7Kp2Q.jpg",
    "view_url": "{{.Base}}/holiday-x7Kp2Q",
    "thumb_url": "{{.Base}}/t/holiday-x7Kp2Q.jpg",
    "width": 4032, "height": 3024, "size": 2483112,
    "embed": { "markdown": "…", "html": "…", "bbcode": "…" },
    "images": [ … every uploaded image … ]
  }
}

With several files, data.images lists each one, data.album_url links the album, and data.errors names any file that didn't make it.

List your images

GET/api/v1/images?page=1&limit=50&q=&sort=new

sort is new, old, views or size. The answer has images, total, page and limit.

Get, rename or delete one image

GET/api/v1/images/{id}
PATCH/api/v1/images/{id}

Body: {"title": "New name"}

DELETE/api/v1/images/{id}
curl -X DELETE -H "Authorization: Bearer ph_yourkey" {{.Base}}/api/v1/images/holiday-x7Kp2Q

Your account

GET/api/v1/me

Email, image count, storage_used and storage_quota in bytes.

GET/api/v1/stats

Public: total images and views on this server. No key needed.

Errors & limits

Failed calls answer {"success": false, "error": "what went wrong"} with a matching status: 400 bad input, 401 missing or wrong key, 404 not found, 429 too fast.

Uploads are rate-limited per IP address; signed-in accounts get four times the guest limit. Accounts have a storage quota you can check at /api/v1/me.
