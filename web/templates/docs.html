API & ShareX

Upload from screenshot tools, scripts, bots and apps. Everything is plain HTTP with JSON answers.

Getting started

  1. Create an account (or sign in).
  2. Open Settings → API keys and create a key. It starts with ph_.
  3. Send it with every request: Authorization: Bearer ph_…

Guests can call /api/v1/upload without a key{{if not .GuestUploads}} when the owner allows it (turned off on this server){{end}}; the answer then includes a private delete_url.

ShareX

Create a key in Settings and press Download ShareX config. Double-click the .sxcu file and ShareX sets everything up: every screenshot is uploaded and the link lands on your clipboard.

Configs made for PixelHop 2 (posting to /api/upload.php) keep working.

Upload

POST/api/v1/upload

Send multipart/form-data with one or more files in file, or image links in url (one per line).

FieldMeaning
fileThe image. Repeat the field for several (up to {{.MaxBatch}}, {{.MaxMB}} MB each).
urlInstead of a file: links to images on the web.
expireDelete automatically: 10m 1h 1d 7d 30d 90d. Leave out to keep forever.
slug0 to use only random characters in the link instead of the file name.
album0 to not group several files into an album.
titleAlbum title, when several files are sent.
listed1 to show the images on your public profile (signed in only). Off by default: images are only reachable by their link.
curl -H "Authorization: Bearer ph_yourkey" \
     -F "file=@holiday.jpg" \
     {{.Base}}/api/v1/upload

Answer:

{
  "success": true,
  "data": {
    "id": "holiday-x7Kp2Q",
    "url": "{{.Link}}/i/holiday-x7Kp2Q.jpg",
    "view_url": "{{.Link}}/holiday-x7Kp2Q",
    "thumb_url": "{{.Link}}/t/holiday-x7Kp2Q.jpg",
    "width": 4032, "height": 3024, "size": 2483112,
    "embed": { "markdown": "…", "html": "…", "bbcode": "…" },
    "images": [ … every uploaded image … ]
  }
}

With several files, data.images lists each one, data.album_url links the album, and data.errors names any file that didn't make it.

Videos, PDFs & big files

Videos (MP4, MOV, WebM, 3GP) and PDFs upload like images and get a page, a poster and a link. Videos lose their location and other metadata at once, then are made smaller in the background (720p H.264, plays on every phone); the link works the whole time. PDFs are compressed right away. The limit is {{.MaxMediaMB}} MB per file.

Files up to {{.MaxMB}} MB can go to /api/v1/upload as usual. Bigger ones are sent in pieces, so a weak connection only repeats one piece:

POST/api/v1/uploads

Body {"name": "recording.mp4", "size": 123456789}. Answers {"id": "…", "chunk_size": 8388608}.

PUT/api/v1/uploads/{id}?offset=N

The raw bytes from N, at most chunk_size. If the offset is wrong you get 409 with "received": continue from there.

POST/api/v1/uploads/{id}/finish

Optional form fields expire, album_id, slug. Answers with the file, like an upload.

Phones & iPhone Shortcut

Android: open this site in Chrome, choose Add to Home screen. {{.Site}} then shows up when you press Share on a photo, video or PDF in WhatsApp, LINE, Gallery or Files.

iPhone: Safari can't add websites to the share sheet, so use a Shortcut (once, about two minutes):

  1. Create an API key in Settings → API keys.
  2. Open Shortcuts, tap +, name it Upload to {{.Site}}. In its settings turn on Show in Share Sheet and accept Images, Media, PDFs and Files.
  3. Add Repeat with Each item in Shortcut Input. Inside it add Get Contents of URL: URL {{.Base}}/api/v1/upload, Method POST, Header Authorization = Bearer ph_yourkey, Request Body Form with a File field named file = Repeat Item.
  4. Still inside, add Get Dictionary Value data, then Get Dictionary Value view_url.
  5. After End Repeat, add Combine Text (Repeat Results, New Lines), Copy to Clipboard and Show Notification “Links copied”.

Now Share → Upload to {{.Site}} on any photo, video or PDF copies the links. One file can be up to 100 MB this way; for bigger videos use this website.

List your images

GET/api/v1/images?page=1&limit=50&q=&sort=new

sort is new, old, views or size. The answer has images, total, page and limit.

Get, rename or delete one image

GET/api/v1/images/{id}
PATCH/api/v1/images/{id}

Body, any of: {"title": "New name", "alt": "Describe it for screen readers", "listed": true}. listed shows it on your public profile (/u/you) and Explore.

DELETE/api/v1/images/{id}
curl -X DELETE -H "Authorization: Bearer ph_yourkey" {{.Base}}/api/v1/images/holiday-x7Kp2Q

Privacy & stats

Every image is unlisted by default: only people with the link see it. Change that with the same PATCH:

{"visibility": "private"}                               // only you (and admins)
{"visibility": "password", "password": "open-sesame"}  // a password page; the file itself is locked too
{"visibility": "unlisted"}                              // back to normal

Locked images never appear on profiles, Explore, oEmbed or the sitemap, and hotlinks to them stop working.

GET/api/v1/images/{id}/stats

Views per day for the last 30 days and the sites that sent visitors (referrers, by host name only).

Resize on the fly

Add a query to any direct link and the server makes (and keeps) that size:

{{.Link}}/i/holiday-x7Kp2Q.jpg?w=800
{{.Link}}/i/holiday-x7Kp2Q.jpg?w=400&h=400&fit=cover
{{.Link}}/i/holiday-x7Kp2Q.jpg?w=1200&format=webp&q=75

w, h up to 4096 (never larger than the original), fit = inside (default) or cover, format = jpeg, png, webp or avif, q 30–95. Each image keeps at most 24 sizes; unusual ones are rounded.

Albums

GET/api/v1/albums
POST/api/v1/albums

Body: {"title": "Trip", "ids": ["holiday-x7Kp2Q", "…"]}. Uploading several files at once also makes an album (send album=0 to skip it).

GET/api/v1/albums/{id}
PATCH/api/v1/albums/{id}

Any of title, description, cover_id, order (all ids in the new order), add and remove (lists of ids).

DELETE/api/v1/albums/{id}

Deletes the album only; its images stay online.

Webhooks

Add an https address in Settings. We POST JSON when you upload (image.uploaded) or delete (image.deleted) an image:

{"event": "image.uploaded", "created_at": 1760600000, "data": { …the image, as in the API… }}

Check the X-PixelHop-Signature header: it is sha256= plus the hex HMAC-SHA256 of the raw body with your webhook secret. Failed deliveries are retried twice.

expected = "sha256=" + hmac_sha256_hex(secret, raw_body)

Embeds & galleries

GET/oembed?url={{.Base}}/{id}

oEmbed for WordPress, Discourse, Notion and friends. Image pages also advertise it in their HTML.

GET/api/v1/users/{username}/images

Public, no key: the images someone chose to show on their profile (limit up to 60). Handy for showing a gallery on your own site or link-in-bio page.

Command line

The pixelhop binary from the releases page is also an uploader:

pixelhop login --server {{.Base}} --key ph_yourkey
pixelhop push screenshot.png photos/*.jpg --expire 7d --format markdown
grim - | pixelhop push -        # from a pipe

--format is page, direct, markdown, html, bbcode or json; --profile shows the images on your profile; --no-album skips the album.

Your account

GET/api/v1/me

Email, image count, storage_used and storage_quota in bytes.

GET/api/v1/stats

Public: total images and views on this server. No key needed.

Errors & limits

Failed calls answer {"success": false, "error": "what went wrong"} with a matching status: 400 bad input, 401 missing or wrong key, 404 not found, 429 too fast.

Uploads are rate-limited per IP address; signed-in accounts get four times the guest limit. Accounts have a storage quota you can check at /api/v1/me.
